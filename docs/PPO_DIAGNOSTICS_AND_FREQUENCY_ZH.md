# PPO 诊断改动与频率迁移说明

本轮按请求修改 `pursuit_rl/learning/ppo.py`、`pursuit_rl/learning/buffers.py`、`pursuit_rl/training/trainer.py` 的诊断链路，附带回归测试和独立参数对照配置。诊断的目标是区分真实奖励尺度、价值自举高估、动作探索与执行器响应问题；它本身不构成 PPO 收敛修复的性能证明。

## 已实现的诊断

| 位置 | 新增内容 |
|---|---|
| buffers.py | 保存 bootstrap 值、TD 残差、原始优势、episode 起点、终止原因、时间和实际推力及角速度；保存各奖励分量；按真实终止、截断、采样边界和失败原因分组统计 |
| ppo.py | 记录归一化前后优势、V/next_V/returns、分位数、极值、非有限值数量；更新前重算动作概率；记录 Actor 总损失、各网络裁剪前梯度范数、最大 minibatch 价值损失和更新后价值误差 |
| trainer.py | 首次异常保存更新前模型、优化器、随机状态、完整 rollout 和环境快照；在异常更新中断时保存证据；提供固定随机策略的完整回合 Critic 校准 |

诊断还记录命令、执行器和原始高斯残差的时间自相关，滞后按 1 步、50 ms、130 ms 取样，并排除跨 reset 的样本。闭环动作相关性包含状态和均值变化，不能单独把它解释成探索噪声相关性；原始策略残差提供更直接的对照。

均值、标准差和极值使用全部有限样本；P01/P50/P99 最多用 8192 个确定性抽样点，日志记录实际样本数。统计不消耗训练随机数。NaN/Inf 在 JSON 中记录数量和空值，避免写出不合法 JSON。

有限值下的 PPO 目标、GAE 和更新结果保持原义。GAE 使用 where 掩码，避免终止边界出现 `0 × NaN` 后污染其他 episode。非有限输入、损失或梯度默认触发中断；普通阈值越界保存首次证据并继续训练。阈值是诊断触发条件，不是裁剪回报或价值的边界。

## 启用和查看

基础数值诊断默认开启，可以直接使用原训练命令。完整回合校准默认关闭，因为 1 kHz 完整 episode 有额外开销。诊断配置独立于原训练 YAML，不改变旧配置哈希和检查点兼容规则。API 可传 `Trainer(..., diagnostics={...})`，命令行通过 `PURSUIT_DIAGNOSTICS_CONFIG` 指定 JSON。

附带的 `configs/diagnostics/numerics.json` 开启每 32 个 rollout 做一次 32 回合完整校准。下面是 CUDA 主机上的诊断基线命令，本次没有执行这轮长训练：

```bash
cd /Users/wujiaqi/work/pursuit_rl_v6_7_2_unified_basic_ppo
PURSUIT_DIAGNOSTICS_CONFIG=configs/diagnostics/numerics.json \
python main.py train \
  --config configs/basic_v67/s0_standard_pure.yaml \
  --out runs/diagnostics_pure_baseline_seed42 \
  --device cuda --simulation-backend torch --seed 42 \
  --total-steps 20000000
```

该路径是本机项目位置，其他机器按实际路径调整。输出目录必须为空。

新增输出位于每次训练的输出目录：

- `diagnostics.jsonl`：每轮数值分布、事件分组和异常原因。
- `train.jsonl`：保留原指标，并新增 Actor 总损失、梯度范数与诊断信息。
- `critic_calibration.jsonl`：显式开启或调用校准后，记录初始 V 与完整折扣回报的分布、偏差和 RMSE。
- `diagnostics/first_anomaly_*.pt` 及同名 JSON：首次异常证据。它是用于重放 rollout 更新的诊断包，不是可直接传入 `--resume` 的训练检查点。

首次异常包在该输出目录已经存在时，后续 resume 不会覆盖它。每轮诊断仍继续记录。NaN 等异常发生在 PPO 更新入口或更新过程中时，会先保存证据再抛出异常；环境采样在 rollout 完成前抛出的异常仍由原训练错误日志处理。

诊断保留一份更新前模型与优化器的内存快照，首次异常时才写出完整 rollout；GPU 统计主要在 rollout 结束后汇总，采样期间不把每步完整状态传到 CPU。新增缓冲区、统计和可选完整回合校准都会增加内存及运行时间，可用 `{"enabled": false}` 关闭。

## 从 20 Hz 迁移到 1 kHz 应如何换算

决策间隔从 0.05 s 缩小到 0.001 s，即同一物理时间内决策数增加 50 倍。但不同参数表示的对象不同，不能统一乘或除 50。

| 参数或机制 | 换算原则 | 当前代码及建议 |
|---|---|---|
| 角速度上限 rad/s | 保持物理值 | 1.2 rad/s 不应改为 0.024 或 60；角度增量由积分时的 dt 处理 |
| 推力 m/s²、最大速度、最大倾角 | 保持物理值 | 先检查单位、动作端点和坐标，再做任务难度消融 |
| 执行器时间常数 s | 保持秒数 | tau=0.13 s 保持不变；离散系数用 `1-exp(-dt/tau)`，当前已有这一处理 |
| gamma | `gamma_new=gamma_old^(dt_new/dt_old)` | 当前 0.9999799902 恰好对应 20 Hz 的 0.999 |
| lambda | 保持原 GAE 时间衰减时，可用 `lambda_new=lambda_old^(dt_new/dt_old)` | 当前 0.9989746601 恰好对应 20 Hz 的 0.95；两者合成的 GAE 时间常数仍只有约 0.956 s |
| n_steps | 按物理采样窗口换算 | 若原来是 256 步，则 20 Hz 为 12.8 s，迁到 1 kHz 同窗口需要 12800 步；当前 2048 步仅 2.048 s |
| total_steps、eval_every、课程阶段步数 | 比较相同物理时间时通常需要乘 50 | 同时记录并行环境数、rollout 数、优化 minibatch 数和物理秒数 |
| 学习率、clip、target_kl、entropy 系数 | 没有统一的频率换算公式 | 根据每轮更新量、KL、梯度与探索效果单独检查；不要全部机械缩放 |

上述 gamma/lambda 的等价关系来自当前可确认配置，并未取得原 95% 成功模型的实际配置。严格迁移应使用那个成功模型的 config 代入，而不是假定它一定用了默认值。

频率敏感性不仅来自数值参数，也来自策略在物理时间中如何探索。连续控制的时间离散化问题见 [Tallec 等的研究](https://arxiv.org/abs/1901.09732)；该论文主要讨论 Q 学习，不能直接把其中的算法修正当作本 PPO 项目的既定解法。

## 探索发生了什么变化

在一阶执行器线性近似、独立白噪声输入下，输出与输入的噪声标准差比为：

`a=exp(-dt/tau)`，`std_out/std_in=sqrt((1-a)/(1+a))`。

角速度执行器 tau=0.13 s 时：

| 决策频率 | 标准差传递比例 |
|---|---:|
| 20 Hz | 约 0.436 |
| 1 kHz | 约 0.062 |

因此相同命令噪声标准差，在 1 kHz 下形成的执行器随机变化可能小约 7 倍。该近似不包含 tanh、状态反馈和闭环均值变化，不能当成实测探索幅度，但足以说明“标准差没塌缩”并不代表探索机制保持不变。

不建议把标准差直接扩大 7 倍：tanh、动作饱和、零推力死区和失控风险都会随之变化。更合理的是按物理时间测试持续探索，例如时间相关策略，或者先做正确实现的低频决策对照。需要用对应的条件分布计算 PPO 概率，不能只在执行动作后加平滑噪声，仍沿用原概率计算。[时间相关探索研究](https://arxiv.org/abs/1903.11524)

当前 Trainer 仍保持每个环境步采样一次动作的训练约定，`policy_interval_steps>1` 只支持评估。此次没有混入动作保持或相关策略实现。

## 奖励函数是否要随频率缩放

应保持相同物理轨迹的累计奖励含义，而不是缩放整个总奖励。

| 奖励类型 | 正确处理 | 当前项目 |
|---|---|---|
| 时间、距离、闭合速度、速度/倾角/边界风险等每秒代价或收益 | 每步使用 `reward_rate × dt` | 当前实现已经乘 dt，不应再把对应权重除以 50 |
| `d_prev-d_now` 的 progress | 差分本身随时间步缩小，保留权重 | 当前已经是差分，不再额外乘 dt 或除以 50 |
| 成功和失败事件 | 每次事件固定给一次 | +30、−25 保持事件意义，不随步频缩放 |
| 势函数 shaping | `gamma_new×Phi(next)-Phi(now)` | 使用正确换算后的 gamma，并统一终止边界；不再整体额外乘 dt |
| 动作变化率平方的连续代价 | `||du/dt||² dt ≈ ||Δu||²/dt` | 当前动作差项为 `dt×||Δu||²`，与变化率代价不同；当前标准实验权重为零 |

最后一项尤其容易混淆。如果沿同一条平滑动作曲线，当前 `sum(dt×||Δu||²)` 在时间步缩小 50 倍后约缩小 2500 倍；若想惩罚物理动作变化率，应重新定义该项。若想惩罚的是独立随机命令的跳变，分析又不同，不能套同一个倍数。此次只做诊断，没有改奖励函数。

成功事件的时间落在离散网格上、积分精度与首次进入判定也会随 dt 略有变化，因此相同轨迹累计奖励的对照应允许可解释的离散化误差。

## Critic 失准的调整顺序

1. **先区分预测与目标谁先出错。** 看每轮的 `rollout.values`、`next_values`、`returns`、原始 `advantage`、`delta`，并对比完整回合 MC 校准。若 V 与 returns 一起膨胀而 MC 正常，优先追查自举反馈与状态信息，而不是把 reward 全体缩小。
2. **避免从膨胀 Critic 继续自举。** 做恢复实验时可保留有效 Actor，但重置 Critic 和它的优化器；必要时固定 Actor，用完整 episode 的 MC 目标拟合新 Critic。现有 `--init-from` 会载入 Actor 和 Critic 两者，不等于仅载入 Actor。此次未增加 Actor Only 初始化命令，也未自动改写旧检查点。
3. **修复任务截止边界。** 如果任务明确要求 40 s 内捕获，截止时的尾部价值应为零；外部采样截断继续用 final observation 自举。新 MC 校准按有限评估任务计算零尾部，日志明确标记。原训练环境的 timeout 语义此次未更改，避免与诊断改动混合。
4. **扩大实质回报覆盖。** 在 gamma 不变时，可先分别测试 8192 步 rollout、3 s GAE，再测试组合。更长 lambda 会增加方差，不能保证改善。
5. **最后再做优化稳定化。** 单独测试 Critic 学习率从 1e-4 降到 3e-5；只有当目标合理但拟合仍不稳时，再考虑 value clipping、Huber 或目标归一化。这些方法可能限制更新或减弱大残差影响，但不会自动消除错误的自举目标。

归一化优势已经存在，它不等于归一化价值目标。当前 Actor 与 Critic 是不同网络，所以巨大 Critic 梯度不会通过共享主干直接覆盖 Actor；它仍会通过错误优势影响策略学习。

如果要采用目标归一化，需要一致处理输出反归一化、bootstrap 和保存/恢复；只对每个 batch 的 returns 减均值除标准差，却继续拿未经一致转换的 V 做下一轮自举，会改变价值含义。[PopArt 相关研究](https://arxiv.org/abs/1602.07714)

对巨大 V，float32 的细小奖励和 TD 差分还可能受到消减误差影响。先把价值校准回任务回报尺度更重要；把全套环境改成 float64 不能替代这一诊断。

## 建议的参数对照

原始配置作为基线，三个单因素配置和一个组合配置已附带：

| 配置 | 相对原 Pure PPO 的变化 |
|---|---|
| `configs/basic_v67/s0_standard_pure.yaml` | 基线 |
| `configs/diagnostics/pure_1khz_rollout_8192.yaml` | 仅 n_steps 改为 8192 |
| `configs/diagnostics/pure_1khz_gae_3s.yaml` | 仅 lambda 改为 0.9996867257539658 |
| `configs/diagnostics/pure_1khz_critic_lr_low.yaml` | 仅 Critic LR 改为 3e-5 |
| `configs/diagnostics/pure_1khz_rollout_8192_gae_3s.yaml` | 采样窗口与 GAE 的组合候选 |

分别使用新的输出目录训练；先看是否仍出现价值高估，再看安全失败比例和独立成功率。原首次 `critic_loss>100` 在约 760 万、1730 万、826 万环境步出现，所以 500 万步没有异常不能当成稳定性通过。本轮没有启动这些长训练。

增大 n_steps 会同时改变每轮样本量、更新间隔与每轮 minibatch 数；附带配置保持其余超参数一致，以便观察该采样设置的效果，但不能声称严格分离了所有由 rollout 长度引发的优化影响。记录实际 KL、early stop 和完成的 minibatch 数再解释结果。
