# PPO 追踪恢复：V6.8.0 改动与本地实测

日期：2026-10-30。已实现代码、完成本地长训练，并附带可直接评估的网络权重。

## 已经得到的结果

推荐路线是 **50 Hz 期望速度策略 + 1 kHz 几何内环，先 BC/DAGGER，再 PPO**。2 米专用任务在 2000 万 PPO 物理步后，独立确定性测试为 **255/256（99.61%）**，成功回合平均捕获时间 **3.912 秒**；另外的随机策略测试为 256/256，平均 3.797 秒。

成功定义沿用现有环境：在失败或截止时间前首次进入捕获球。测试为阶段 0，初始距离 10–30 米、目标速度 0–5 m/s，截止 40 秒，保留机体域随机化。尚未验证高机动目标、持续保持 2 米误差或真机。

| 路线与训练阶段 | 独立测试成功率 | 成功回合平均捕获时间 | V 对确定性执行回报的 RMSE（参考） |
|---|---:|---:|---:|
| 2 米：BC/DAGGER 初始化 | 256/256（100.00%） | 5.904 s | 0.146 |
| 2 米：随后 PPO 2000 万步 | 255/256（99.61%） | 3.912 s | 0.223 |
| 5 米：BC/DAGGER 初始化 | 256/256（100.00%） | 4.038 s | 0.146 |
| 5 米：随后 PPO 2000 万步 | 256/256（100.00%） | 3.181 s | 0.127 |
| 真正 1 kHz CTBR：初始化 | 256/256（100.00%） | 5.326 s | 0.208 |
| 真正 1 kHz CTBR：随后 PPO 200 万步 | 256/256（100.00%） | 5.295 s | 0.211 |

表中 critic 单位为统一乘 0.1 后的学习奖励。critic 学习的是随机采样策略的价值；表中对确定性执行回报的误差只是参考，严格匹配采样策略的校准应看随机测试 RMSE 0.158。PPO 前后使用同一 CPU 初始状态集合，已逐回合核对位置和目标速度。2 米任务共同成功的 255 个回合，PPO 平均比初始化快 1.990 秒，其中 255 个回合更快。

恢复追踪的主要贡献是新的控制接口和 BC 初始化；PPO 随后改善捕获速度，没有提高初始化已经达到的成功率，2 米独立测试还出现 1 例超时，该例最近距离为 2.044 米。保留 `bc.pt` 作为稳定参照，不能只报告 `best.pt`，也不能把这称为纯 PPO 从零收敛。

## 为什么要这样改

旧诊断中，PD 在同分布任务上成功，但 15 次纯 PPO 训练大多几乎无法接近目标。部分实验的 critic 已比较准确，控制仍失败。因此继续微调 critic 学习率、rollout 或 GAE 的收益有限。

新的验证证明，原机体约束下可训练出有效的网络策略：真正每毫秒推理的 CTBR 网络也能完成 256/256。并不能据此认定旧失败只有一个原因，但它排除了“1 kHz 下网络一定无法控制”的判断。动作接口、探索的物理时间尺度、执行器状态观测以及有效的初始策略，需要一起处理。

主方案让网络负责目标追踪所需的期望速度；内环只基于自身速度和姿态生成机体控制，不读取目标位置替网络追踪。它仍按 1 ms 更新，保留原推力/角速度限制和执行器延迟，新增加速度限幅 8 m/s²、内环目标倾角上限 35°。

直接 CTBR 方案每毫秒重新调用网络，用上一 raw action 构造相关时间 20 ms 的条件高斯。采样和 PPO likelihood 使用同一个条件分布，避免在动作采样后额外滤波而破坏比率计算。两条路线均补充实际推力、角速度、剩余时间、边界余量与动作记忆。

## 2 米目标必须参与训练

本地也做了失败对照：5 米初始化模型直接改按 2 米测试为 240/256；为 5 米任务继续优化 2000 万步后，改按 2 米测试反而只剩 195/256。优化宽捕获球不能保证更高的捕获精度。

因此默认运行脚本使用 `velocity_50hz_2m.json`，从示教、critic 初始化到 PPO 都使用 2 米终止条件。上述 255/256 来自这条专用路线；没有把 5 米指标当作 2 米指标。显式跨半径测试仍可通过 `--capture-radius` 完成，并在报告中记录。

## critic 与奖励的具体处理

1. 当前已初始化策略先随机采样完整回合，用不含 bootstrap 的真实 MC 回报预训练 critic 600 次。2 米任务拟合 RMSE 从约 2.919 降到 0.104；这是拟合集误差，独立确定性测试 RMSE 为 0.223，随机测试为 0.158。
2. 每约 200 万物理步检查完整 MC 校准；超过 1.5 时只额外拟合 critic。此次三条路线都没有触发额外重拟合。原先 actor KL 停止连带中断 critic 的问题，在新路线中分离处理。
3. 实际使用 20 秒折扣时间、3 秒优势衰减时间。每 K 个 1 ms 物理步决策一次时，`gamma=exp(-K*0.001/20)`，`lambda=exp(-K*0.001/3)/gamma`。rollout 用“决策数”和“对应秒数”一起记录。
4. 一次宏动作奖励是内部逐物理步奖励的折扣和，再统一乘 0.1。原本已带 dt 的时间型奖励不重复乘频率；距离进度不再乘一次 dt；终止事件奖励不乘 1/50 或 1/1000。统一 0.1 是数值尺度，和频率换算分开。
5. 40 秒是真正任务截止，停止 bootstrap，潜势终止值清零；另加未缩放超时惩罚 25。首次命中/失败后冻结该回合的奖励和最终观测，再重置。

两条 50 Hz 路线各执行 2000 万 PPO 物理步，对应 100 万决策样本、62 轮 PPO 更新；各另用约 120 万物理步收集示教。MC 与评估还使用额外轨迹。因此这不是同总交互预算的纯 PPO 消融。

训练中 2 米 rollout 完成 4086 回合、5 米完成 5562 回合，全部成功。2 米周期验证成功率范围为 98.44–100%，最终为 100%；独立测试为 99.61%。2 米 rollout 的 |V| 最大约 3.480，重算 log probability 最大差为 0，没有触发数值异常快照。

## 如何在服务器使用

解压 `pursuit_rl_v6_8_0_rescue.zip` 后进入新目录，使用原 Python/PyTorch 环境。新代码未覆盖原服务器工程。

```bash
# 先直接验证随包的 2 米 PPO 模型。
python scripts/rescue.py evaluate \
  --checkpoint pretrained/velocity_50hz_2m_ppo20m_seed42.pt \
  --profile configs/rescue/velocity_50hz_2m.json \
  --device cuda --episodes 256 --out runs/v680_pretrained_2m_eval.json

# 再用服务器环境从头复现实验，默认先跑约 200 万 PPO 物理步。
DEVICE=cuda bash scripts/run_rescue.sh

# 同目录续训到累计 2000 万步，不重复 BC。
DEVICE=cuda PPO_STEPS=20000000 bash scripts/run_rescue.sh
```

结果看 `runs/v680_rescue/velocity_50hz_2m/seed_42/comparison.json`，其中分别列出初始化、最佳、最新网络。确认初步效果后用 `SEEDS="42 43 44"` 检查多训练种子。直接 1 kHz CTBR 对照可设 `PROFILE=configs/rescue/ctbr_1khz_bc.json`。

完整参数、观测索引、断点语义、源码位置及其他对照配置见包内 `RESCUE_README.zh-CN.md`。新接口 checkpoint 不兼容旧 `main.py`；加载器会检查动作单位、频率、观测和任务契约。

## 验证范围

本地环境为 macOS arm64、Python 3.9.21、PyTorch 2.8.0.dev20250424、CPU 单线程，训练种子只有 42。服务器此前为 CUDA 环境，CPU 与 CUDA 的随机数流不同，不能把新旧数字当作严格配对或多种子结论。新模型的同种子前后对比则已核对初始状态完全一致。

完整测试 156 项通过、2 项跳过，另补做旧诊断实现的更新一致性审计 1 项通过。两个默认跳过项为外部源码对照与真实 CUDA；外部源码对照已另外通过，CUDA 仍待服务器验证。执行脚本通过语法检查、真实小任务首次运行和延长预算续训验证。异常包测试确认保存的是更新前网络、优化器和对应 rollout，可以重算行为 likelihood。

初始工作副本的源码指纹与服务器诊断一致。原本的本地项目路径已不存在，因此交付独立完整版本。随包 `local_validation/` 含原始评估、逐轮日志与配对核对结果；`pretrained/` 含六个可直接评估的网络。

方法依据：[PPO](https://arxiv.org/abs/1707.06347) 使用基于采样策略概率比率的更新；[GAE](https://arxiv.org/abs/1506.02438) 提供优势估计的偏差与方差权衡；[DAgger](https://arxiv.org/abs/1011.0686) 用学习者访问的状态补充示教标签。本项目效果由上述本地实验支持。
